## Objetivo

Usar `specs/` como puerta de entrada para nuevas capacidades funcionales y tecnicas del producto.

## Regla operativa

- cada feature priorizada crea una carpeta en `specs/`
- cada feature incluye `spec-funcional.md`, `spec-tecnica.md` y `spec-tareas.md`
- QA y Ops deben poder trazar la feature hacia `qa/` y `ops/`
- la base reutilizable de trabajo vive en `plantillas/fase-4-sdd/`
