## Objetivo
Validar como sera la experiencia mediante spec inicial y prototipo antes de cerrar SDD tecnico o construir front/back.

## Nivel
Producto validable y prototipo.

## Posicion metodologica
```text
Product Design
  -> SPDD - spec inicial + prototipo
  -> HTML5 Prototype rapido para validar flujo
  -> Penpot si se requiere diseno formal, colaboracion o handoff
  -> Prototype Validation
  -> SDD - specs tecnicas front/back
  -> Construccion Front + Back
```

## Entradas
- `specs/<feature>/product-design.md`
- `specs/<feature>/spec-funcional.md` inicial o borrador funcional,
- flujos UX,
- reglas visibles,
- restricciones de permisos,
- criterios de negocio.

## Salidas por feature
- `specs/<feature>/spdd-frontend.md`
- `specs/<feature>/prototype.md`
- `specs/<feature>/prototype-validation.md`
- `specs/<feature>/ui-test-cases.md`
- `specs/<feature>/traceability.md`
- `specs/<feature>/prototype-html5/` cuando se use prototipo rapido HTML5.

## Que valida SPDD
- pantalla o flujo correcto,
- campos requeridos,
- estados loading, empty, error, success y unauthorized,
- validaciones visibles,
- restricciones por rol/perfil documentadas,
- componentes principales,
- divergencias entre spec inicial y prototipo,
- observaciones resueltas o aceptadas.

## Modos de prototipo
| Modo | Uso recomendado | Resultado |
|---|---|---|
| HTML5 | primera iteracion rapida, navegacion, estados UI, permisos y mocks | `prototype-html5/` versionado y navegable en navegador |
| Penpot | diseno formal, colaboracion UX, design system y handoff | link/export Penpot registrado |
| Wireframe markdown | excepcion para baja superficie visual o validacion temprana | pantallas y decisiones trazadas |

## Gates de prototipo
- `gate-prototype-ready` valida que existe prototipo revisable y suficiente para pedir feedback.
- `gate-spdd-approved` valida que el prototipo fue revisado y aprobado o aceptado con observaciones.

## Regla de salida
No cerrar SDD ni construir una feature visual sin `gate-spdd-approved`, salvo que la feature documente explicitamente que no tiene superficie visual.

## Ubicacion de artefactos
Esta practica se define en Fase 2 UX/UI, pero los artefactos por feature viven en `specs/<feature>/`, no en `docs/`. Esa ubicacion es intencional: los artefactos SPDD alimentan SDD directamente y deben estar junto a las specs tecnicas de la feature. Las plantillas base estan en `plantillas/fase-4-sdd/`.
