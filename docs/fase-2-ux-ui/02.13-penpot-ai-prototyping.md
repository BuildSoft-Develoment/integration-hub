## Objetivo
Usar Penpot como herramienta de prototipo formal para SPDD, asistida por IA mediante prompts o MCP, despues de definir Product Design y `spdd-frontend.md`.

## Posicion metodologica
```text
Product Design
  -> SPDD
  -> Prototipo rapido HTML5 si se necesita velocidad
  -> Prototipo formal Penpot si se necesita aprobacion visual, colaboracion o design system
  -> Validacion UX
  -> gate-spdd-approved
  -> SDD
  -> Construccion Angular + Backend
```

## Cuando usar Penpot
- Se requiere prototipo visual formal.
- Hay colaboracion con UX/UI, negocio o stakeholders externos.
- Se requiere design system, tokens, componentes o handoff visual.
- El proyecto es enterprise y la aprobacion visual debe quedar registrada.
- Ya existe un flujo validado en HTML5 y se necesita formalizarlo.

## Penpot con IA
Penpot puede usarse en dos niveles:

| Modo | Uso | Evidencia |
|---|---|---|
| Prompt asistido | La IA genera instrucciones para que UX o producto creen el archivo Penpot | prompt generado, link/export y validacion |
| MCP | Un cliente IA compatible lee o modifica un archivo Penpot abierto | link Penpot, cambios registrados y validacion humana |

## Flujo recomendado con MCP local
1. Crear proyecto en Penpot.
2. Crear o abrir el archivo de diseno de la feature.
3. Iniciar el MCP local, por ejemplo `npx @penpot/mcp@stable`.
4. Cargar el plugin MCP desde `http://localhost:4400/manifest.json` dentro de Penpot.
5. Conectar el cliente IA compatible con MCP.
6. Usar `product-design.md`, `spdd-frontend.md` y `ui-test-cases.md` como entradas.
7. Crear o ajustar paginas, frames, componentes, variantes y links de navegacion.
8. Registrar link, prompt o export en `specs/<feature>/prototype.md`.
9. Registrar decision de validacion en `specs/<feature>/prototype-validation.md`.
10. Aplicar `gate-prototype-ready` y luego `gate-spdd-approved` si hubo aprobacion humana.

## Regla
Un prompt Penpot no equivale a prototipo aprobado.

```text
prompt Penpot != prototipo aprobado
prototipo Penpot + validacion registrada = evidencia para gate-spdd-approved
```

## Salidas esperadas por feature
```text
specs/<feature>/
  prototype.md
  prototype-validation.md
  ui-test-cases.md
```

Si se genera un prompt formal:

```text
ai/prompts/generated/crear-prototipo-penpot-<feature>.md
```

## Red flags
- SPDD sin pantallas ni estados UI.
- Penpot creado sin trazabilidad a RF/HU.
- IA modifica Penpot sin revision humana.
- Link Penpot registrado pero sin validacion.
- Se declara `gate-spdd-approved` solo por existir un prompt.
