## Objetivo
Definir como Product Owner, UX, BA, negocio y agentes IA convierten RF/HU y notas de negocio en claridad de producto antes de prototipar o escribir codigo.

## Nivel
Producto.

## Roles
| Rol | Responsabilidad |
|---|---|
| Product Owner | prioriza necesidad, objetivo y valor |
| BA | ordena reglas, actores y criterios |
| UX/UI | define journeys, pantallas, estados y componentes |
| Negocio | valida lenguaje, flujos y excepciones |
| IA como analista/UX assistant | estructura, detecta huecos, propone alternativas y prepara entregables |

## Flujo canonico
```text
RF / HU / notas de negocio
  -> IA estructura producto
  -> dos alternativas si hay ambiguedad
  -> decision de producto recomendada
  -> problema, usuarios, journey, hipotesis, alcance y metricas
  -> validacion inicial con negocio
  -> insumo para SPDD
  -> gate-ux-ready
```

## Product Design Output
La salida de Product Design es un producto o flujo validado conceptualmente. Todavia no es codigo ni spec tecnica detallada.

Debe cubrir:
- problema,
- objetivo,
- usuarios/personas,
- journey,
- hipotesis de solucion,
- metricas de exito,
- alcance y no alcance,
- features candidatas,
- validacion inicial.

## Reglas de operacion
- `/ux` es el comando principal de Fase 2.
- `/document` puede alimentar Fase 2, pero no reemplaza `/ux`.
- Product Design no reemplaza SPDD; prepara insumos para prototipo y validacion.
- Toda decision de producto no confirmada queda como supuesto o pregunta abierta.

## Checklist de salida
- [ ] El problema y objetivo estan claros.
- [ ] Personas o usuarios principales estan identificados.
- [ ] El journey conceptual esta descrito.
- [ ] Hay alcance y no alcance.
- [ ] Hay metricas de exito.
- [ ] Hay validacion inicial o preguntas abiertas.
- [ ] La salida alimenta SPDD.
