<a id="base-transversal-sugerida"></a>
## Base transversal sugerida

- `src/` para codigo fuente con base neutral en `backend/`, `frontend/` y `shared/`.
- `tests/` para pruebas automatizadas en `unit/`, `integration/`, `e2e/` y `fixtures/`.
- `qa/` para artefactos de calidad organizados por fase.
- `ops/` para artefactos operativos organizados por fase.
- `docs/` para documentos de definicion y gobierno.
- `specs/` para features bajo `SDD`.

<a id="equivalencias-del-proyecto-real"></a>
## Equivalencias del proyecto real

### Codigo

- `src/` del template equivale funcionalmente a:
  - `platform-app/src/`
  - `frontend/apps/`
  - `frontend/libs/`

### Pruebas

- `tests/` del template equivale funcionalmente a:
  - `platform-app/src/test/`
  - `frontend/apps/web-e2e/`
  - pruebas frontend ejecutadas desde el workspace `Nx`

### Arquitectura y diagramas

- fuente editable de arquitectura:
  - `likec4/`
- salida compatible actual:
  - `docs/architecture/dist/`
- exportaciones estaticas recomendadas:
  - `diagramas/`

### Operacion

- `ops/`, `qa/`, `ci/` y `releases/` coinciden semanticamente con la estructura del template

<a id="regla-principal"></a>
## Regla principal

La alineacion al template en este proyecto es semantica y documental. No se debe mover `platform-app/` ni `frontend/` solo para imitar la forma del template.
