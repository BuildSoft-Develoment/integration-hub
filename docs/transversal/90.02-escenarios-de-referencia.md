## Objetivo

Mostrar que un escenario no es una sola etiqueta, sino una combinacion de dimensiones para tomar decisiones mas consistentes.

## Regla principal

No elegir un unico "escenario". Definir al menos estas tres dimensiones:

- madurez del producto
- estilo de arquitectura
- modelo de despliegue

## Dimensiones recomendadas

### Madurez

- `MVP`
- `Enterprise`

### Arquitectura

- `Monolito modular`
- `Microservicios`

### Despliegue

- `On-premise`
- `Cloud`
- `Hibrido`

## Combinacion actual recomendada para este proyecto

Para `Integration Hub`, la combinacion mas consistente con el estado actual es:

- `Madurez: MVP evolucionable`
- `Arquitectura: Monolito modular`
- `Despliegue: Hibrido`

Esto encaja con la estructura real del repositorio:

- backend concentrado en `platform-app/`
- frontend concentrado en `frontend/`
- integraciones externas, seguridad y observabilidad ya consideradas desde el arranque

## Ruta recomendada

1. Revisar `../../escenarios/README.md`.
2. Usar `90.03-checklist-seleccion-escenario.md` para justificar la combinacion vigente.
3. Reflejar cualquier cambio de escenario en arquitectura, despliegue y `ADR`.
