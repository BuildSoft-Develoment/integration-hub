## Objetivo

Explicar como se interpreta el escenario vigente del proyecto para tomar decisiones coherentes en arquitectura, despliegue y operacion.

## Regla principal

El escenario no se resume en una sola etiqueta. En este repositorio siempre debe evaluarse como combinacion de:

- madurez del producto
- estilo de arquitectura
- modelo de despliegue

## Dimensiones aplicadas al proyecto

### Madurez

- estado vigente: `MVP evolucionable`
- implicancia: se prioriza velocidad con orden documental y trazabilidad suficiente para crecer

### Arquitectura

- estado vigente: `Monolito modular`
- implicancia: la complejidad de integracion vive dentro de una plataforma unica con fronteras internas por dominio y provider

### Despliegue

- estado vigente: `Hibrido con foco on-prem`
- implicancia: la solucion debe convivir con restricciones corporativas, secretos externos, observabilidad y promociones controladas por ambiente

## Lectura operativa del escenario

La combinacion vigente explica por que hoy existen:

- `platform-app/` como backend principal
- `frontend/` como consola administrativa separada por workspace pero integrada en despliegue
- `ops/` y `ci/` como soporte formal a salida y operacion
- `docs/` y `specs/` como control estructurado de crecimiento

## Regla de mantenimiento

Si el proyecto cambia a microservicios, cloud dominante o gobierno enterprise mas estricto, esta base debe actualizarse antes de seguir expandiendo fases o features.
