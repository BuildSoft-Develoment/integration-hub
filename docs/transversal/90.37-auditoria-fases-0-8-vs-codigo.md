Revisar la documentacion generada de fases `0` a `8` contra el codigo existente en
`platform-app/` y `frontend/`, identificando alineacion, drift documental y gaps de
validacion.

## Alcance revisado

- Documentacion base exigida por `AGENTS.md`.
- Fases `0` a `8` bajo `docs/`.
- Features `specs/001` a `specs/007`.
- Contratos `contracts/api/openapi.yaml` y `specs/*/api-contract.md`.
- Backend Quarkus en `platform-app/`.
- Frontend Angular/Nx en `frontend/`.
- Artefactos QA, Ops, CI, releases y LikeC4.

## Resultado ejecutivo

La documentacion describe correctamente el stack principal y la estructura real del
repositorio: backend `Quarkus` en `platform-app/`, frontend `Angular 21/Nx` en
`frontend/`, persistencia `PostgreSQL`, seguridad `OIDC/Keycloak`, `OpenTelemetry`,
`Quinoa`, specs `001` a `007`, QA, Ops, CI y releases.

El codigo tambien respalda la mayoria de capacidades declaradas: fuentes
`filesystem`/`ftp`/`sftp`/`rest`, readers `txt`/`csv`/`xls`/`xlsx`/`json`/`xml`,
tareas `FILE_READ`/`DB_WRITE`/`DB_EXECUTE_SP`/`DB_EXECUTE_FN`/`REST_CALL`/
`NOTIFICATION`, scheduler, tema del sistema, auditoria y UI por dominios.

Los principales riesgos estan en la trazabilidad fina: contratos API incompletos frente
al codigo real, QA formal marcada como completa aunque las evidencias siguen pendientes,
gates `pending`, matriz RBAC canonica no consolidada y drift alrededor de MongoDB como
destino operativo.

## Hallazgos

### P1 - Contratos API incompletos frente al backend y frontend reales

`contracts/api/openapi.yaml` y algunos `specs/*/api-contract.md` no cubren todos los
endpoints reales de Quarkus ni todos los endpoints consumidos por Angular.

Endpoints reales sin cobertura OpenAPI consolidada:

- `POST /api/process-executions/{processDefinitionId}`.
- `GET /api/query/source-definitions`.
- `GET /api/query/reader-definitions`.
- `GET /api/query/connection-definitions`.
- `GET /api/query/process-definitions`.
- `GET /api/query/process-schedules`.
- `GET /api/connection-definitions/{connectionDefinitionId}/jdbc-metadata/schemas`.
- `GET /api/connection-definitions/{connectionDefinitionId}/jdbc-metadata/columns`.
- `GET /api/connection-definitions/{connectionDefinitionId}/jdbc-metadata/procedure-parameters`.
- `GET /api/connection-definitions/{connectionDefinitionId}/jdbc-metadata/functions`.
- `GET /api/connection-definitions/{connectionDefinitionId}/jdbc-metadata/function-parameters`.

Evidencia en codigo:

- `platform-app/src/main/java/com/integrationhub/platform/api/resource/process/ProcessExecutionResource.java`.
- `platform-app/src/main/java/com/integrationhub/platform/api/resource/catalog/CatalogQueryResource.java`.
- `platform-app/src/main/java/com/integrationhub/platform/api/resource/connection/ConnectionDefinitionResource.java`.
- `frontend/libs/features/processes/src/lib/api/process-api.service.ts`.
- `frontend/libs/features/sources/src/lib/api/source-api.service.ts`.
- `frontend/libs/features/readers/src/lib/api/reader-api.service.ts`.
- `frontend/libs/features/connections/src/lib/api/connection-api.service.ts`.
- `frontend/libs/features/schedules/src/lib/api/schedules-api.service.ts`.

Impacto: los consumidores externos y validadores contract-first no ven toda la API real.
Ademas, `check-openapi-coverage` y `check-api-documented` pasan porque comparan contratos
documentales entre si, no el codigo real contra los contratos.

Accion recomendada: ampliar `api-contract.md` de las features `003`, `005` y `006`,
regenerar `contracts/api/openapi.yaml` y agregar un check `Quarkus resources -> OpenAPI`.

### P1 - QA formal incompleta pese a checklist marcado como completo

`docs/transversal/90.11-checklist-entregables.md` marca Fase 6 como completa, pero las
evidencias QA oficiales siguen en estado pendiente y solo cubren `001` a `004`.

Evidencia:

- `qa/fase-6-qa/evidencias/001-catalogo-fuentes.md`.
- `qa/fase-6-qa/evidencias/002-catalogo-readers.md`.
- `qa/fase-6-qa/evidencias/003-diseno-y-ejecucion-procesos.md`.
- `qa/fase-6-qa/evidencias/004-observabilidad-y-auditoria.md`.
- `docs/fase-6-qa/cobertura/mapa-casos-y-evidencias.md`.

Impacto: la fase 6 no cumple su propio criterio de salida trazable. Las features
`005` a `007` no tienen caso/evidencia QA canonica equivalente en `qa/fase-6-qa/`.

Accion recomendada: completar evidencias reales, agregar QA para `005` a `007` o marcar
explicitamente la fase como parcial/no cerrada.

### P2 - Gates y evidencia TDD mantienen estado pendiente

Las matrices de `specs/*/traceability.md` declaran RF implementados, pero los gates
`gate-sdd-approved`, `gate-build-ready`, `gate-qa-passed`, `gate-deploy-ready` y
`gate-operations-ready` aparecen como `pending` en las features revisadas.

Ademas, varias `tdd-evidence.md` mantienen `pending` en RED/GREEN o validacion humana,
especialmente `005`, `006` y `007`.

Impacto: el codigo puede estar construido, pero la evidencia de proceso no esta cerrada.

Accion recomendada: separar claramente `codigo implementado` de `gate aprobado` y no
usar checklists globales como completados hasta cerrar los gates aplicables.

### P2 - Drift en RBAC canonico

Las specs y el codigo usan roles reales `platform-admin`, `integration-admin`, `operator`
y `auditor`. Sin embargo, `docs/fase-3-arquitectura/03.08-auth-authz.md` conserva una
matriz generica `viewer`/`editor`/`approver`/`admin` y dice que la matriz real debe vivir
en un ADR. La matriz de huecos tambien reconoce que falta una tabla unica endpoint x rol.

Evidencia:

- `platform-app/src/main/java/com/integrationhub/platform/api/resource/**` con
  `@RolesAllowed`.
- `frontend/libs/core/services/src/lib/auth/auth-access.service.ts`.
- `docs/fase-3-arquitectura/03.08-auth-authz.md`.
- `docs/fase-1-analisis-requerimientos/01.01-matriz-huecos-fase-1.md`.

Impacto: riesgo de divergencia entre permisos documentados, API y UI.

Accion recomendada: crear o actualizar un ADR/matriz endpoint x rol con los roles reales
del producto y enlazarlo desde fase 1, fase 3 y specs.

### P2 - MongoDB aparece como destino operativo en arquitectura, pero el codigo lo trata como parcial

El codigo permite catalogar `MONGODB`, pero la prueba de conexion devuelve
`MongoDB test connection is not implemented yet`, `ConnectionType.isJdbc()` excluye
MongoDB y `DB_WRITE` resuelve `DataSource` JDBC. El frontend tambien informa que el
camino `DB_WRITE` para MongoDB no esta implementado.

Evidencia:

- `platform-app/src/main/java/com/integrationhub/platform/service/connection/ConnectionCatalogService.java`.
- `platform-app/src/main/java/com/integrationhub/platform/domain/ConnectionType.java`.
- `platform-app/src/main/java/com/integrationhub/platform/provider/task/dbwrite/DbWriteTaskProvider.java`.
- `frontend/libs/core/services/src/lib/i18n/dictionaries/es.ts`.
- `likec4/integration-hub.likec4`.

Impacto: la arquitectura/LikeC4 puede sobreprometer escritura MongoDB frente al estado
real del backend.

Accion recomendada: documentar MongoDB como `catalogado/parcial` hasta implementar
conectividad y escritura, o implementar el proveedor real y su evidencia.

### P3 - Documento de seguridad mantiene contenido de plantilla

`docs/fase-3-arquitectura/03.08-auth-authz.md` incluye instanciaciones de stacks no usados
en este repo (`Node + Next.js`, `Spring Boot`, `Spring + React`) y una referencia a
`ADR-002 Configuracion y secretos`, mientras que el `ADR-002` existente es de principios
de diseno SOLID.

Impacto: ruido documental y referencias ambiguas en fase 3.

Accion recomendada: recortar el documento a Quarkus + Angular + Keycloak reales y mover
contenido de plantilla a referencias transversales si se quiere conservar.

## Verificaciones ejecutadas

```text
node scripts\generate-openapi.mjs --check
node ci\scripts\check-openapi-coverage.mjs
node ci\scripts\check-api-documented.mjs
node ci\scripts\check-test-documented.mjs
```

Resultado:

- `generate-openapi --check`: OK, OpenAPI coincide con `api-contract.md`.
- `check-openapi-coverage`: OK, 100% sobre endpoints declarados en traceability.
- `check-api-documented`: OK.
- `check-test-documented`: OK, pero reporta que no hay features en fase >= 6 segun su
  criterio interno.

Interpretacion: los checks documentales actuales no detectan drift codigo-vs-contrato.

## Prioridad recomendada

1. Corregir contratos API y OpenAPI contra recursos Quarkus y servicios Angular.
2. Completar QA formal o bajar el estado de Fase 6 a parcial.
3. Consolidar matriz RBAC endpoint x rol con roles reales.
4. Alinear MongoDB como alcance parcial o implementar conectividad/escritura real.
5. Limpiar contenido de plantilla en `03.08-auth-authz.md`.
