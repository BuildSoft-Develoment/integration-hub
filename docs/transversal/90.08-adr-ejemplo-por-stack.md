## Objetivo

Explicar como se conecta una decision de stack con la disciplina de `ADR` del proyecto.

## Regla de uso

- Crear `ADR` cuando una decision cambie estructura, tecnologia, despliegue o riesgo operativo.
- Mantener trazabilidad con arquitectura, stack y escenario.
- Usar `plantillas/fase-3-arquitectura/adr.md` como base.
- Revisar `ejemplos/fase-3-arquitectura/adr-ejemplo.md` como referencia de profundidad.

## Aplicacion en este proyecto

Si `Integration Hub` cambia alguno de estos puntos, debe dejar `ADR`:

- paso de monolito modular a microservicios
- cambio del proveedor de identidad
- cambio de estrategia de secretos o despliegue
- cambio de stack frontend o backend
