## Objetivo

Definir como debe trabajarse en el repositorio segun el nivel de incertidumbre y el estado de madurez del entregable.

## Modo exploratorio

Usar cuando:

- el problema todavia es ambiguo
- hay varias opciones tecnicas o funcionales
- se requiere comparativa, spike o investigacion

Salidas minimas:

- supuestos
- opciones evaluadas
- recomendacion
- siguiente aterrizaje a `docs/`, `ADR` o `specs/`

## Modo estructurado

Usar cuando:

- ya existe arquitectura base
- hay backlog o expectativa de entrega
- la capacidad pasa a construccion, QA, deploy u operacion

Salidas minimas:

- documentos oficiales en `docs/`
- `ADR` si cambia arquitectura o tecnologia
- `specs/` si una feature entra a ejecucion
- evidencia en `qa/`, `ops/`, `ci/` o `releases/`

## Regla vigente para este repositorio

`Integration Hub` ya debe operar principalmente en `modo estructurado`. El modo exploratorio sigue existiendo, pero como paso previo breve antes de consolidar salidas oficiales.
