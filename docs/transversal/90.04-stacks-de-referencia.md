## Objetivo

Ubicar el stack vigente del proyecto dentro del conjunto de stacks comparables que el repositorio contempla como base de decision.

## Stacks comparables

- `Quarkus + Angular/Nx`
- `Spring Boot + React`
- `Node + Next.js`
- `Java Monolith`

## Stack vigente del proyecto

- backend: `Quarkus`
- frontend: `Angular 21 + Nx`
- empaquetado UI: `Quinoa`
- identidad y acceso: `Keycloak`
- persistencia principal: `PostgreSQL`
- observabilidad: `OpenTelemetry`

## Por que este stack sigue siendo consistente

- encaja con el escenario de monolito modular
- soporta integraciones empresariales y despliegue controlado
- permite separar claramente backend, frontend, seguridad y observabilidad
- ya tiene trazabilidad formal en arquitectura, `ADR`, `specs/`, `qa/` y `ops/`

## Relacion con el repositorio

- `../../stacks/README.md` conserva las fichas comparables
- `docs/fase-3-arquitectura/` documenta la decision ya aplicada
- cualquier cambio de stack debe reflejarse tambien en `ADR`
