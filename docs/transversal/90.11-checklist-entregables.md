## Objetivo

Usar este checklist como control rapido para confirmar que el repositorio deja entregables minimos por fase y por dominio aplicado.

## Checklist por fase

### Fase 0

- [x] vision del proyecto
- [x] roadmap
- [x] estimacion inicial
- [x] roles y responsabilidades

### Fase 1

- [x] analisis de requerimientos
- [x] detalle por modulos, casos y backlog inicial

### Fase 2

- [x] resumen UX/UI
- [x] journeys, pantallas, wireframes y validacion

### Fase 3

- [x] arquitectura
- [x] decisiones de tecnologia
- [x] plan de despliegue
- [x] `ADR`
- [x] `LikeC4`

### Fase 4

- [x] `SDD`
- [x] `specs/`
- [x] trazabilidad a QA y Ops

### Fase 5

- [x] estructura de construccion real documentada
- [x] mapa de backend y frontend
- [x] verificacion tecnica base

### Fase 6

- [x] plan de pruebas
- [x] casos, evidencias y defectos en `qa/`

### Fase 7

- [x] checklist de salida
- [x] pipeline, runbook, rollback y evidencia en `ci/`, `ops/` o `releases/`

### Fase 8

- [x] operacion continua
- [x] monitoreo, metricas y operacion en `ops/fase-8-operacion/`
