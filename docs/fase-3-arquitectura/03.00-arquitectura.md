## Alcance del documento

Este documento resume la solucion tecnica real del proyecto. Debe poder leerse junto con `ADR`, `LikeC4`, anexos arquitectonicos y el plan de despliegue sin contradicciones.

## Estado actual de la arquitectura

- El producto se implementa como una plataforma de integracion con backend `Quarkus`, frontend `Angular/Nx`, persistencia `PostgreSQL`, seguridad `OIDC/Keycloak` y observabilidad con `OpenTelemetry`.
- La UI administrativa vive en `frontend/` y se empaqueta con `Quinoa` dentro de `platform-app/`.
- La arquitectura aplica separacion por dominios funcionales y por providers para fuentes, readers, conexiones y tareas.
- El frontend adopta contratos de extension por contribuciones para preparar
  modulos internos y futuros plugins instalables sin acoplarlos al shell.
- La operacion y el despliegue se aterrizan en `ops/`, `ci/` y `releases/`.

## Estilo de arquitectura

La solucion responde hoy a un monolito modular sobre `Quarkus` con frontend desacoplado a nivel de workspace, pero integrado en despliegue. No se usa una malla de microservicios; se prioriza coherencia operacional, menor complejidad de despliegue y extensibilidad interna por providers.

## Frontend

- `frontend/` aloja un workspace `Nx` con `Angular 21`.
- La app `web` implementa la consola administrativa para `overview`, catalogos, procesos, ejecuciones, schedules y auditoria.
- La UI usa `Angular Material`, `CDK`, `TailwindCSS v4`, `Signals` y guards por seccion.
- `Quinoa` integra el build del frontend dentro del runtime `Quarkus`.
- El shell frontend consume contribuciones declarativas (`navigation`, `routes`,
  `workspaces`, `actions`, capabilities e i18n) en vez de exigir que cada
  modulo modifique directamente la navegacion global.
- La primera SPI implementada combina `APP_PLUGIN_MANIFESTS` y
  `APP_NAVIGATION_CONTRIBUTIONS`: los manifests declaran identidad/version y el
  shell valida duplicados por `id`, rutas y workspaces antes de montar la UI.
- El router Angular materializa rutas desde manifests con lazy loading y guarda
  trazabilidad `pluginSource`/`pluginRouteId` en `data` de la ruta.
- Los workspaces internos, como `/audit/*`, consumen contribuciones declarativas
  (`APP_WORKSPACE_CONTRIBUTIONS`) filtradas por grupo y capability.
- Las acciones de UI extensibles se declaran como metadata (`command`,
  `navigation` o `external-link`) y se validan antes de exponerse; los comandos
  son identificadores simbolicos para que el shell conserve el control de
  ejecucion.
- La ejecucion de acciones se centraliza en `AppActionExecutor`: navega por
  Router, abre solo enlaces externos `https://` y delega comandos a
  `APP_ACTION_COMMAND_HANDLERS` registrados por provider estatico.
- La consulta de acciones visibles se centraliza en `AppActionQueryService`,
  filtrando por ubicacion, grupo, tipo, permisos y disponibilidad del handler,
  y adaptando la metadata al contrato visual `ActionBarAction` cuando una
  feature necesita renderizar acciones.
- La feature `connections` consume ya este flujo para acciones masivas:
  `platform` declara las acciones, la feature registra handlers locales y la UI
  renderiza/ejecuta mediante `AppActionQueryService` y `AppActionExecutor`.
- El runtime frontend carga un catalogo desde `/plugins/catalog.json`.

> **Correccion (reingenieria 2026-07-31).** Este parrafo decia que el catalogo "no puede ejecutar
> codigo remoto". Es falso, y se contradecia con un documento de esta MISMA carpeta:
> [`guia-autor-plugins.md`](guia-autor-plugins.md) describe paso a paso como se publica un plugin
> que ejecuta codigo. El backend tiene `GrpcRemotePluginTransport` para invocar sidecars remotos, y
> el catalogo de UI se verifica con firma ECDSA P-256 antes de cargarse.
>
> Lo que SI es cierto, y es la restriccion real: el plugin no puede saltarse la verificacion de
> firma ni declarar rutas fuera de la politica de navegacion. La extensibilidad esta **gobernada**,
> que no es lo mismo que ausente.
- El contrato del catalogo externo se publica como
  `/plugins/catalog.schema.json` y el catalogo real lo referencia con
  `$schema`.
- El catalogo externo se valida con `npm run validate:plugins` antes de
  publicarse, bloqueando rutas desconocidas, capabilities no soportadas,
  duplicados, acciones con rutas no instaladas, enlaces externos no HTTPS,
  campos fuera del contrato e incompatibilidad de `platformVersion`.

## Backend

- `platform-app/` concentra API, seguridad, scheduler, ejecucion de procesos y acceso a datos.
- El backend expone capacidades de catalogo, ejecucion, auditoria y operacion.
- La extension funcional se apoya en managers y providers por dominio, **y ademas** en plugins
  gobernados: verticales que registran sus tipos por el SPI, y sidecars remotos por gRPC con su
  catalogo de UI firmado. "Arbitrarios" es lo que no se admite; extensibles, si.
- La logica de integracion debe preservar trazabilidad por proceso, tarea y archivo.

## Base de datos

- `PostgreSQL` es la persistencia principal para catalogos, ejecuciones, auditoria y staging.
- La integridad de la operacion depende de correlacionar proceso, tareas, archivos y eventos.
- Las conexiones a sistemas externos pueden usar `JDBC` u otros mecanismos segun provider, pero la plataforma conserva una base interna central.

## Seguridad

- La autenticacion y autorizacion se apoyan en `OIDC` con `Keycloak`.
- La UI y la API deben respetar roles operativos como `Platform Admin`, `Integration Admin`, `Operator` y `Auditor`.
- La seguridad no se limita a login: tambien cubre secretos, permisos por seccion y auditoria funcional.

## Integraciones

- fuentes `filesystem`, `ftp`, `sftp` y `rest`
- readers por formato `txt`, `csv`, `xls`, `xlsx`, `json` y `xml`
- conexiones externas para persistencia o invocacion de servicios
- tareas configurables como `FILE_READ`, `DB_WRITE`, `REST_CALL` y `NOTIFICATION`

## Observabilidad

- la plataforma requiere logs, metricas y trazas correlacionadas
- `OpenTelemetry` cubre la base de trazabilidad distribuida
- la operacion necesita visibilidad sobre scheduler, ejecuciones fallidas, errores de integracion y rendimiento por tarea
