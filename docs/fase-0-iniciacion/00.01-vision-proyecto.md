# Vision del proyecto

## Objetivo

Definir la vision y el alcance base de `Integration Hub` como plataforma de integracion configurable.

## Que resuelve

La plataforma permite configurar fuentes, readers y tareas para ejecutar integraciones de forma gobernada, auditable y observable desde una consola web y un backend Quarkus.

## Problema que aborda

- integraciones batch dispersas y poco trazables
- dependencia de scripts puntuales por integracion
- baja gobernanza sobre ejecuciones, errores y reprocesos
- poca visibilidad operativa y dificultad para auditar

## Alcance actual

- fuentes `filesystem`, `ftp`, `sftp`, `rest`
- readers `txt`, `csv`, `xls`, `xlsx`, `json`, `xml`
- tareas `DB_WRITE`, `DB_EXECUTE_SP`, `DB_EXECUTE_FN`, `REST_CALL`, `NOTIFICATION`
- seguridad con `Keycloak`
- persistencia y auditoria en `PostgreSQL`
- trazabilidad con `OpenTelemetry`
- UI administrativa en `Angular 21` integrada con Quinoa

## Actores principales

- `platform-admin`
- `integration-admin`
- `operator`
- `auditor`
- sistemas externos y servicios corporativos

## Resultado esperado

- catalogos configurables de fuentes, readers y procesos
- ejecuciones manuales y programadas
- trazabilidad por ejecucion, tarea y archivo
- capacidad de reproceso y seguimiento operativo

## Restricciones actuales

- el codigo fuente ejecutable se mantiene en `platform-app/` y `frontend/`
- los secretos y configuraciones operativas no deben moverse de rutas ya usadas por scripts y runtime
- la salida a produccion depende de hardening operativo adicional
