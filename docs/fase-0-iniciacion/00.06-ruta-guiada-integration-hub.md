## Objetivo

Ofrecer una lectura unica de punta a punta para entender como se traduce `Integration Hub` a artefactos concretos del repositorio.

## Recorrido recomendado

1. Leer la vision en `00.01-vision-proyecto.md`.
2. Leer el analisis en `../fase-1-analisis-requerimientos/01.00-analisis-requerimientos.md`.
3. Revisar la arquitectura en `../fase-3-arquitectura/03.00-arquitectura.md`.
4. Revisar `../fase-4-sdd/04.00-spec-driven-development.md`.
5. Abrir las features base en `../../specs/`.
6. Revisar QA en `../../qa/`.
7. Revisar operacion en `../../ops/`.

## Features principales del proyecto

- `001-catalogo-fuentes`
- `002-catalogo-readers`
- `003-diseno-y-ejecucion-procesos`
- `004-observabilidad-y-auditoria`
- `005-catalogo-conexiones`
- `006-programacion-procesos`
- `007-tema-del-sistema`
- **`008-mensajeria-pagos`** — el money-path SWIFT MT101. Es la linea de trabajo dominante desde
  junio y la que concentra las decisiones de arquitectura mas recientes (ADR-016, 017, 020, 021,
  023). Quien quiera entender el producto hoy, empieza por aqui.

Paso obligatorio antes de tocar nada estructural: leer
[los ADR](../fase-3-arquitectura/adr/README.md). Varias decisiones -la frontera motor/vertical, la
separacion de esquemas, el despliegue nativo- estan congeladas por tests y romperlas falla el build.

## Resultado esperado

Al terminar esta ruta deberia quedar claro:

- como se define el producto,
- como se baja a arquitectura,
- como entra una feature a `specs/`,
- como se conecta con QA y operacion,
- como se usa IA como apoyo dentro del proyecto.
